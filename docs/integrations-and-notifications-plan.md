# 接入与通知 · 搭建大纲

> 目标：让「研协」不只靠人盯着浏览器。个人 AI agent（比如 dots）能把平台接走、能读到项目在发生什么；平台发生事情时，能主动推到你自己的通知系统里；真正需要你动手的事，还能发一封邮件到你邮箱。
>
> 这份大纲分两半：**第一到十一节是人话**，不懂技术也能看完并拍板；**从附录 A 开始才是给开发看的细节**。
>
> 一句话结论：**能做，分 6 步，一个人大约 2–3 周。第一周结束，dots 这类 agent 就能读上项目、线程和收件箱；第二周邮件上线。**

## 一、一句话说清楚要加什么

现在的情况是：项目里发生的一切，**只有打开网页才能看见**。想用自己的 agent 接、想推到自己的通知系统、想不在电脑前也知道，都没有门。

要加三样东西：

1. **一把给机器的钥匙**——让外部 agent 不用借你的浏览器登录，也能安全地调接口。
2. **一套订阅服务**——发生事情时，服务器主动把消息送到你指定的地址（或者保持一条实时通道一直推）。
3. **一个邮局**——需要人处理的事，发一封邮件提醒你。

再加一份**接入说明书**和示例代码，别人照着就能接。

## 二、我们手里已经有什么（比想象的近）

平台里其实已经有三块地基，只是没对外开：

| 已有的东西             | 它是什么                                                                                              | 为什么正好能用上                                                                         |
| ---------------------- | ----------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------- |
| **事件流水账**         | 每次改动（发消息、开线程、改文档、审阅、认领……）都会在 `events` 表里记一条，每个项目从 1 开始连续编号 | 它天然就是「订阅源」。断线重连还能说「我上次看到第 1024 条」，服务器补发后面的，不重不漏 |
| **收件箱（待我处理）** | 已经把「什么需要人来做」算好了：决策卡、请你审阅、有人 @ 你、认领冲突、派给你的活、线程完成           | 邮件不用再发明一套规则，**收件箱有新东西 → 发邮件**，一条规则就够                        |
| **门卫规则**           | 角色（所有者/导师/成员/访客）+ 项目成员校验 + 逐条过滤（个人线程只给主人、收件箱只给本人）            | 新开的三条通道全部复用这套规则，不会出现「推力把私聊推出去了」                           |

**缺的就是这几块**：钥匙、两个订阅口（Webhook 和实时流）、邮局、说明书。

## 三、四间新房 + 一份说明书

| 编号 | 名字                             | 用生活的话说                                    | 解决什么问题                                                    |
| ---- | -------------------------------- | ----------------------------------------------- | --------------------------------------------------------------- |
| 1    | **令牌**（门禁卡）               | 给 agent 发一张卡，刷卡进门，不用借你的登录状态 | dots 能调接口读写                                               |
| 2    | **Webhook**（订报纸）            | 你留一个地址，一有新闻报社就送到你家门口        | 接到你自己的通知系统（飞书机器人、自建服务、手机 App 网关都行） |
| 3    | **实时流 SSE**（一直开着的电话） | 电话不挂，服务器有动静就顺着线说一句            | 你在内网、没有公网地址也能实时收                                |
| 4    | **邮件**（邮局）                 | 重要的事，寄一封到你邮箱                        | 不打开网页也知道有活要干                                        |
| 5    | **说明书**                       | 一页「怎么接」+ 可复制的示例                    | 别人（和他们的 agent）不用问你                                  |

## 四、整体怎么走

```
                    ┌────────────── 研协服务器 ──────────────┐
                    │                                        │
  浏览器 ───────────┤  网页界面（这次基本不动）              │
                    │                                        │
  dots / 脚本 ──────┤  ① 令牌（Bearer）→ 读写接口            │
                    │        │                               │
                    │        ▼                               │
                    │  事件总线（每次改动写一条事件）        │
                    │        │                               │
                    │        ├──→ /ws        浏览器实时（已有）│
                    │        ├──→ ③ /stream  实时流（新）    │
                    │        ├──→ ② Webhook  推到你的地址（新）│
                    │        └──→ ④ 通知中心 → 邮件（新）    │
                    └────────────────────────────────────────┘
```

要点：**所有新通道都从同一本流水账出发**。所以不会出现「网页看到了、邮件没收到」这种不一致。

## 五、六步走，每一步都能单独上线

原则：不搞「全做完才能用」。每一步结束都有能演示的效果。

### 第 0 步 · 拍板（半天）

- **做什么**：定下第六节那三件事，确认这份大纲。
- **产出**：这份文档 + 接口草案（`API.md` 里追加一节）。
- **不做**：不写代码。

### 第 1 步 · 钥匙：令牌（2–3 天）

- **你会看到**：设置里多一个「接入」，点一下生成一串 `srh_pat_...`。复制给 dots，它就能读项目和收件箱了。不想要了点「撤销」，**立刻失效**。
- **做什么**：
  - 新建一张 `api_tokens` 表（只存**哈希**，不存原文，跟现在的登录会话一个思路）。
  - 服务器认 `Authorization: Bearer srh_pat_...` 这个头，效果等于「这个人登录了」。
  - 给令牌加：限项目、可设过期、只读/可写两种、每分钟调用上限、最后使用时间。
- **风险**：低。但改的是登录入口（安全敏感），需要维护者 review（LGTM）。

### 第 2 步 · 订阅：Webhook（3–4 天）

- **你会看到**：填一个网址、勾选「哪些事通知我」，之后你的服务就会收到带签名的 POST。设置页有投递记录（成功/失败/第几次重试），失败会自动重试，连续失败会自动停用并提醒你。
- **做什么**：
  - 两张表：订阅地址 `webhook_endpoints`、投递记录 `webhook_deliveries`。
  - 一个后台投递器（跟现在文献库的进程内队列同一种写法，不需要 Redis）。
  - 签名（防伪造）、时间戳（防重放）、超时 10 秒、退避重试 5 次。
  - **推送前必须用和网页一样的过滤规则**——个人线程、个人收件箱的内容不能推给别人的地址。
- **风险**：中。出站请求必须走现成的公网守卫（`websearch/net.ts` 的 `fetchPublic`），否则等于给服务器装了一个能打内网的工具。

### 第 3 步 · 实时流：SSE（1–2 天）

- **你会看到**：一行 `curl -N` 就能一直收到事件；断网重连自动从上次的编号续上。
- **做什么**：`GET /api/v1/stream`，复用事件表和同一套过滤器；25 秒一次心跳；支持 `Last-Event-ID` 续传。
- **说明**：比 Webhook 更适合「没有公网地址」的人。可以和第 2 步并行做。

### 第 4 步 · 邮件（3–4 天）

- **你会看到**：
  - 收件箱有新东西 → 一封合并邮件（默认 5 分钟内合并，不一封一封轰炸）。
  - 能选「立即 / 每小时 / 每天早上一封 / 关闭」，能设免打扰时段。
  - 设置页有「发一封测试邮件」按钮，失败了会告诉你原因。
  - 每封邮件底下有「不想收？点这里」。
- **做什么**：
  - 一张 `email_outbox` 表 + 发信器（先入库再发，发信失败不影响网页操作）。
  - 3 个中文模板（单条提醒、合并提醒、每日摘要），深色/浅色邮箱都能看。
  - 退订链接（签名，不用登录也能点）、每人每小时上限、失败记录。
- **关键设计**：**只认收件箱**。平台已经把「什么值得打扰人」算过了（决策卡 > 审阅 > @ > 冲突 > 指派 > 完成），邮件不需要第二套规则。默认只发前三类，「线程完成」只在每日摘要里出现。
- **风险**：中。需要邮箱 + 域名配置，否则容易进垃圾箱（见第七节）。

### 第 5 步 · 让 dots 动手：MCP（3–5 天）

- **你会看到**：dots 里填「地址 + 令牌」，它就能像用本地工具一样调用研协：看项目、读线程、发消息、建待办、查收件箱。
- **做什么**：
  - 一个 `/api/v1/mcp` 入口（现在主流的 MCP 远程接法），把平台能力包成 8–9 个工具。
  - 按令牌权限开关：只读令牌看不到「发消息/建待办」这些工具。
  - 每次调用记审计。
- **风险**：中高。这是新的**公开写入口**，所以放在最后——令牌、限流、审计、过滤都就位了再开。

### 第 6 步 · 打磨（2–3 天）

- 接入文档页（带可复制的 curl / SSE / MCP 配置）。
- 投递失败、退信、限流的面板。
- 用真实 dots 跑一遍端到端，把结论写进 PR。
- 顺手把「免打扰 / 摘要时间」做成跟账号走的偏好。

## 六、需要你拍板的三件事

**1. 邮件走哪家的邮箱？**

| 方案                        | 说明                                                                                             | 我的建议                                  |
| --------------------------- | ------------------------------------------------------------------------------------------------ | ----------------------------------------- |
| A. 现成邮件服务的 SMTP      | QQ 企业邮、阿里云邮件推送、腾讯云 SES、Resend、Amazon SES、Gmail 应用专用密码……填 4 个参数就能用 | **推荐**。日发几十封基本免费，10 分钟配好 |
| B. 自建邮局（Postfix 之类） | 要维护 IP 信誉、退信、黑名单，很容易被当成垃圾邮件                                               | 不建议，为了几十封邮件不值                |

选 A 的话需要：**一个域名**（多数邮件服务要求）+ **一个发件地址**（如 `notify@你的域名`）+ 三条 DNS 记录（SPF/DKIM/DMARC，服务商会给现成的）。

**2. 你的通知系统有公网地址吗？**

- 有（云服务器、Vercel、公司网关都算）→ Webhook 最省事，第 2 步就够了。
- 没有（只在你自己电脑/内网）→ 用第 3 步的实时流，或让 dots 定时来问。

**3. dots 是「只看」还是「能动手」？**

- 建议先给：**读全部 + 发消息 + 建待办**。
- 暂不给：改文档正文、删东西、改项目设置。
- 这决定第 5 步给几个工具，也决定风险大小。

以下两个我可以直接按默认值做，你不回也行：

- 谁能生成令牌：建议**所有登录成员都能给自己生成**，访客不行。令牌能做的事不会超过本人在网页上能做的（越不了权），泄露了也能随时撤销；想更严可以加个开关只放开给所有者 / 导师。
- 邮件默认频率：建议**合并后 5 分钟一封**，免打扰 22:00–08:00。

## 七、要准备的东西和成本

| 要什么               | 用途                                 | 大概成本              |
| -------------------- | ------------------------------------ | --------------------- |
| 域名（已有站点就有） | 邮件发件域名、webhook 回调地址       | 已有                  |
| 一个邮箱地址         | 发信人，如 `notify@你的域名`         | 0 元起，按量几十块/年 |
| 三条 DNS 记录        | SPF / DKIM / DMARC，防进垃圾箱       | 免费                  |
| HTTPS（已有 Caddy）  | Webhook 只允许 https                 | 已有                  |
| **不需要**           | 新服务器、Redis、Kafka、消息队列服务 | 0                     |

技术上全部跑在现有那一个 Node 进程里，不增加运维负担。

## 八、安全底线（这几条不让步）

1. 令牌**只显示一次**，数据库里只存哈希；随时可撤销，撤销后立刻失效。
2. 令牌可以限定项目、设过期、设成只读。
3. Webhook 只接受 `https`，**拒绝内网地址**，带签名 + 时间戳（防伪造、防重放）。
4. 邮件里只放**标题、一句话、链接**；正文和思路要登录才能看。
5. 必须有免打扰、退订、每人每小时上限——通知系统最怕变成骚扰。
6. 所有外发都留审计，保留 30 天，能在设置页看到。
7. **任何外发都不包含**旁聊、个人线程、别人的收件箱内容（复用现有的逐条过滤）。

## 九、这轮先不做

- 短信、微信、手机 App 推送（真要做，Webhook 加个转发就够，不用改平台）。
- 自建邮件服务器。
- 多机部署（现在单进程内存总线够用；以后换成 Postgres 通知机制，接口不变）。
- 反向同步（把 dots 的笔记、日程拉进研协）。
- 给外部 agent 开「管理」能力（改成员、改设置、删项目）。

## 十、出问题怎么关（每个新功能都有总开关）

新功能全部**默认关闭**，用环境变量打开，出问题不用回滚代码：

| 开关                 | 关掉之后                                 |
| -------------------- | ---------------------------------------- |
| `API_TOKENS_ENABLED` | 所有令牌立刻失效，网页登录照常           |
| `WEBHOOK_ENABLED`    | 不再向外投递，队列里的记录保留           |
| `EMAIL_ENABLED`      | 不再发信，待发的信留在队列里，打开后继续 |
| `MCP_ENABLED`        | 外部 agent 不能再用工具，网页不动        |

另外：单个订阅可以在设置页停用；单个令牌可以撤销；邮件可以给某个人关掉。**网页本身永远是最后一道保险**——所有新通道都只是「多一种看法」，不承担唯一入口。

- [ ] 我的个人工作区里发消息，别人的 webhook 收不到。

# 附录 A · 给开发看的细节

## A1 新增数据表（5 张，新文件 `db/schema/integrations.ts`，迁移从 `0011` 起）

都按仓库约定：主键 `<前缀>_<ULID>`、时间 `timestamptz`、作者用 `ActorRef` 冗余。

| 表                   | 关键字段                                                                                                                                                                    | 说明                                                              |
| -------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------- |
| `api_tokens`         | user_id, name, token_hash(唯一), token_hint(前 8 位，列表里认人), scopes(`read`/`write`), project_ids(空=全部), expires_at, last_used_at, revoked_at                        | 只存 SHA-256。查找直接按 hash 走唯一索引                          |
| `webhook_endpoints`  | project_id(空=所有我加入的项目), owner_user_id, url, secret, event_types(空=默认集合), enabled, failure_streak, disabled_reason, last_success_at                            | secret 只写不读，接口只返回掩码                                   |
| `webhook_deliveries` | endpoint_id, project_id, event_seq, event_type, payload(jsonb), status(pending/success/failed/dropped), attempts, next_attempt_at, response_status, response_snippet, error | 唯一索引 (endpoint_id, project_id, event_seq) 做幂等；30 天后清理 |
| `email_outbox`       | user_id, to_email, kind(instant/digest/test), subject, body_text, body_html, payload(jsonb), status, attempts, next_attempt_at, sent_at, error                              | 先入库再发，发信失败不影响业务事务                                |
| `notify_prefs`       | user_id(主键), email_enabled, frequency(instant/hourly/daily/off), quiet_start, quiet_end, kinds(text[]), opted_out_at, updated_at                                          | 每人一行。**不改 `users` 表**，避免动到登录相关的核心表           |

发件地址直接取 `users.email`（注册时必填且唯一），因此 v1 不需要邮箱验证流程；等要发营销类内容时再加。

## A2 接口清单（都挂在 `/api/v1`，都要同步 API.md）

| 方法       | 路径                                          | 权限             | 作用                                  |
| ---------- | --------------------------------------------- | ---------------- | ------------------------------------- |
| GET        | `/auth/me/tokens`                             | 网页登录         | 我的令牌列表（只返回 hint，不回原文） |
| POST       | `/auth/me/tokens`                             | 网页登录         | 新建，**响应里返回一次原文**          |
| DELETE     | `/auth/me/tokens/:id`                         | 网页登录（本人） | 撤销                                  |
| GET        | `/auth/me/webhooks`                           | 网页登录         | 我的订阅                              |
| POST       | `/auth/me/webhooks`                           | 网页登录         | 新建（校验 https + 公网地址）         |
| PATCH      | `/auth/me/webhooks/:id`                       | 本人             | 改地址 / 事件 / 开关                  |
| DELETE     | `/auth/me/webhooks/:id`                       | 本人             | 删除                                  |
| POST       | `/auth/me/webhooks/:id/test`                  | 本人             | 发一条测试事件                        |
| GET        | `/auth/me/webhooks/:id/deliveries`            | 本人             | 投递记录（游标分页）                  |
| POST       | `/auth/me/webhooks/:id/redeliver/:deliveryId` | 本人             | 手动重投                              |
| GET        | `/stream`                                     | 令牌或 Cookie    | SSE 事件流                            |
| GET        | `/auth/me/notify`                             | 网页登录         | 邮件偏好                              |
| PUT        | `/auth/me/notify`                             | 网页登录         | 改偏好（频率、免打扰、类别）          |
| POST       | `/auth/me/notify/test`                        | 网页登录         | 发测试邮件                            |
| GET        | `/notify/unsubscribe?token=`                  | 无需登录         | 一键退订（签名校验）                  |
| POST / GET | `/mcp`                                        | 令牌             | MCP 远程入口                          |

两条额外规矩：

- **令牌管理接口只认网页登录会话**，Bearer 令牌不能创建或撤销令牌——否则一张泄露的令牌可以给自己续命。
- 路径沿用现有 `/auth/me/pins` 的习惯，前端不用记两套命名。

## A3 事件信封、签名、重试

**Webhook 请求体**（和 `/ws` 的 event 同形，另加一句人话摘要）：

```json
{
  "id": "whd_01JB...",
  "type": "inbox.created",
  "projectId": "prj_01JB...",
  "threadId": null,
  "seq": 1024,
  "createdAt": "2026-10-30T09:12:31.000Z",
  "actor": { "kind": "agent", "id": "agt_01JB...", "name": "协调者" },
  "data": {
    "id": "inb_01JB...",
    "kind": "review",
    "title": "李四 请你审阅《方法》",
    "href": "/p/prj_.../reviews/..."
  },
  "text": "李四 请你审阅《方法》"
}
```

`text` 只对默认事件集合精修（`inbox.created`、`message.created`、`thread.updated`、`decision.updated`、`review.updated`、`claim.conflict`、`report.updated`），其余退回 `<actor.name> · <type>`。

**请求头**：

```
X-SRH-Event: inbox.created
X-SRH-Delivery: whd_01JB...
X-SRH-Timestamp: 1730291551
X-SRH-Signature: t=1730291551,v1=<hex hmac_sha256(secret, "1730291551." + body)>
```

接收方校验：时间戳与当前时间差 ≤ 5 分钟；签名用 `crypto.timingSafeEqual` 比较。

**投递策略**：超时 10 秒；`2xx` 成功；`429`/`5xx`/网络错误重试；重试间隔 `1m / 5m / 30m / 2h / 6h`；5 次后 `dropped`；连续 20 次失败自动停用订阅，并给主人建一条收件箱提醒。出站统一走 `fetchPublic`（公网守卫 + 手动跟随重定向），`user-agent` 改成 `SRH-Webhook/1.0`。

**SSE 格式**：

```
id: prj_01JB...:1024
event: message.created
data: {"seq":1024,"type":"message.created",...}

: ping
```

25 秒一次心跳；`retry: 5000`；`Last-Event-ID` 取 `<projectId>:<seq>` 续传；缺口 > 1000 条时发 `event: resync` 让客户端重拉（和 `/ws` 阈值一致）。

## A4 邮件规则

- 触发：`inbox.created`（同一用户、同一批合并）。默认只发 `decision` / `review` / `conflict` / `mention`；`assignment` 和 `finished` 进每日摘要。
- 合并窗口：即时模式 5 分钟，每小时模式整点，每日模式 09:00（用户本地时区先固定 `Asia/Shanghai`）。
- 免打扰：窗口内只入库不发，窗口结束后合并成一封。
- 退订：`HMAC(userId, "unsub")` 签名链接，点开即写 `notify_prefs.opted_out_at`；退订只影响邮件，站内收件箱照常。
- 每封邮件底部固定：项目名、为什么收到（"你在研协订阅了…"）、退订、设置链接。
- 上限：每用户每小时 6 封，超出顺延。
