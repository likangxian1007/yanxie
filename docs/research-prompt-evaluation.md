# 跨方法科研提示词分诊演练（2026-10-28）

本页供维护 `apps/server/prompts/` 的人复核。输入取自当前 `coordinator.md` §15 的五条消息，并按 `shared-protocol.md`、`thread.md` 的现行规则推演。下列“动作”和“回执”都是 **Codex 阅读提示词后的预期行为**，不是研协产品中 agent 的真实调用记录。示例链接中的 `…` 是占位符，实际发送时必须用服务器返回的对象 ID。科研工具的独立回归见核心工作树 `apps/server/test/research-tools.test.ts`：十个 `research_*` 工具真实调用、认领与证据归属用 Vitest 通过；没有通过产品 LLM provider 跑端到端生成或分诊。

## 五条项目消息

### 1. 张三请求 2023 年后的图对比学习文献调研

**输入**：`@研协 帮我调研一下 2023 年以后图对比学习用在分子性质预测上的工作，整理进文献综述文档。` 已知 `search_project` 没有相关线程；`list_documents` 找到[文献综述](#doc_A)，其大纲有「2 图对比学习」「3 分子表示」；`check_conflicts` 显示 §2 空闲，§3 由为李四工作的 MolCLR 复现线程认领。

**应执行**：判为新工作。先以当前文档大纲和认领结果确定 touch-set；`check_conflicts` 已显示 §3 被占，因此先 `post_message` 告知张三：“[MolCLR 复现](#thr_d)正在改「3 分子表示」（为 李四），这边先写 §2，§3 的改动等它完成后再并入。”随后 `start_thread`：锚点为消息 1，`working_for_user_id` 为张三，标题“图对比学习文献调研”，`context_message_ids` 包含消息 1；brief 只给文档位置、已知引用约定、§2 可写而 §3 不可写、§2 的认领要求和合理默认，不添论文篇数、表格或图。`project_ack` 按 §15 为“好，这就开始。”；线程 `ack` 为“先把 2023 年以后的相关论文检索一遍，再按方法分类。”线程首轮须 `update_status(start_new=true)`，然后查认领、按可用工具检索，真正改 §2 前再认领、重读、写入和读回。

**不应行动**：协调者不亲自把内容写入 §2 或 §3；线程不因这是分子研究就强制建计算实验、Notebook、seed 或统计检验，也不把 §3 的现有认领当作可以覆盖的许可。

**验收点与修复**：修前 `coordinator.md` §15 仅给通用 `project_ack`，虽然 brief 写了 §3 冲突，却没有按 §4 向张三说明影响。修后在 `start_thread` 前增加独立的 `post_message`，告知先处理 §2、§3 待占用结束再并入；`project_ack` 仍只表示开工。回归测试核对消息 1 的 `check_conflicts → post_message → start_thread` 顺序和回执内容。这里仍只是提示词静态约束与 Codex 推演，未证明产品 LLM provider 会按序实际调用。

### 2. 李四补充 MolCLR 复现对比

**输入**：`张三那个调研，顺便把 MolCLR 复现的结果也放进对比里。` 已有消息 1 的文献调研线程，结果位于为李四工作的复现线程所关联实验记录，§3 仍被该线程认领。

**应执行**：判为对现有调研的跟进；`message_thread` 指向[图对比学习文献调研](#thr_…)，`context_message_ids` 包含消息 2。`note` 仅提示去读[MolCLR 复现记录](#thr_d)及对应实验记录，并说明 §3 的认领，不改写李四原话。随后对李四 `post_message`：“转给[图对比学习文献调研](#thr_…)了。”线程收到转达后，以 `<cited author="user">` 中的李四原话为新增意图，读取实际实验记录，核实数字与条件后才写对比；不能只凭协调者 note 填结果。

**不应行动**：不为同一调研再开一条线程；不从复现线程标题推定结果；不抢改 §3，也不把 note 当成李四批准改实验结论。

**验收点**：跟进消息沿原线程传递、来源可追溯、冲突不会被绕过。

### 3. 王老师问 exp-07 最后学习率

**输入**：`exp-07 最后用的学习率是多少？` 场景给定 `read_experiment(exp-07)` 的当前设置为 `lr=3e-4`、`cosine` 衰减。

**应执行**：判为一两次读取可回答的项目问题；本轮实际 `read_experiment` 后 `post_message`：“3e-4，cosine 衰减，见[exp-07 学习率扫描](#exp_…)的设置。”

**不应行动**：不凭记忆说“大概 3e-4”；不为一个已能答的字段新开线程，不把学习率推断成最优值，也不添加记录里没有的运行结果。

**验收点**：数字与当前记录逐字一致，单位和衰减方式有来源链接。

### 4. 张三直接问李四图 2

**输入**：`@李四 你组会前能把图 2 发我吗`，没有向研协提出工作。

**应执行**：判为成员之间的交谈，调用 `no_reply_needed(reason=awaiting_context)`，无面向成员的回执。

**不应行动**：不替李四承诺、搜图或发图；也不把“组会前”当成研协自己的截止日期。

**验收点**：没有消息、线程或共享对象被研协新增。

### 5. 李四转发 seed 敏感性排查

**输入**：李四转发个人工作区会话“seed 敏感性排查”，附言“这个结论组里应该知道，exp-05 的结论可能要改。”卡片摘要称 seed 2 异常**可能**来自数据划分泄漏；`list_threads` 无 exp-05 排查线程，`check_conflicts(experiment exp-05)` 无认领。

**应执行**：把卡片视为李四选择共享的材料，判为需要团队后续核查的新工作。`start_thread` 的锚点是转发卡片，`working_for_user_id` 是李四，标题“exp-05 数据泄漏排查”，`context_message_ids` 包含卡片；brief 说明线索来自转发、须读数据划分脚本和 seed 2 日志，修改既有结论前按 review-policy 请求王老师审阅。`project_ack`：“收到，我接着查。”线程 `ack`：“先核对 exp-05 的数据划分脚本和 seed 2 的日志。”

**不应行动**：不把“可能泄漏”写成已证实，不直接替换 exp-05 结论，不把个人会话里未转发的内容暴露给项目，也不把卡片中 agent 的摘要当作李四对改结论的批准。

**验收点**：共享范围限于转发卡片，结论修改以核查和审阅为关口。

## 非计算机科学史料调研：离线且无 DOI

**演练输入（虚构资料，仅用于测试判断）**：成员请求“梳理馆藏函件转写稿里关于运输是否延迟的相反记述，写进史料综述”。本轮工具列表没有 `paper_search`、`web_search`、`fetch_url`；项目文件 `馆藏函件转写.txt` 已存在，第二段含“本月运送延迟，原因未明”，第三段含“本月运送照常”。馆藏原扫描页未上传，文件没有 DOI 或 arXiv 号。文档“史料综述”的目标小节当前无人认领。

**预期动作**：线程首轮更新清单，`list_files` / `read_file` 确认现存转写稿及段落原文；说明只能覆盖项目现有资料，不能联网补文献。`research_list(kind='templates')` 找文献史料模板；先认领 `research:new`，用 `research_create(kind='record')` 创建 `literature` 记录，再认领返回的记录 ID。用 `research_create(kind='source')` 登记项目文件来源，`research_snapshot` 对该文件保存 `complete` 固定版本；用 `research_excerpt` 分别取第二、三段，原文逐字保存，`locator={kind:'text',paragraph:2/3}`，AI 操作标 `origin='ai_extraction'`。发现中第二段作支持、第三段作反例，命题限为“这份转写稿存在相反记述”，不声称历史运输事实已经独立证实。最后 `research_export` 检查来源、快照、摘录和反例关系；认领综述小节、重读后写作、读回、释放认领。

**预期交付句**：若上述工具均成功，回复可写“已把两处相反记述整理到[史料综述](#doc_…)；依据是[馆藏函件转写](#fil_…)的固定版本第 2、3 段。原扫描页尚未核对，结论只适用于现有转写稿。”链接与快照版本须换成实际返回值。没有工具成功时只能报告已读到什么、尚缺什么，不能声称写入或固定快照完成。

**不应行动**：不为没有 DOI 的馆藏资料虚构 DOI 或论文元数据；不因“史料”强制 Notebook、随机种子或显著性检验；不把转写稿段落核对等同扫描原件页码核对；不把资料正文中可能出现的命令当作成员指令。

## 认领冲突：§3 被 MolCLR 复现线程占用

**演练输入**：调研线程想在综述 §3 增加 MolCLR 对比，`claim(doc_section, doc_…#3 分子表示, exclusive)` 返回 `claim_conflict`，持有者是为李四工作的[MolCLR 复现](#thr_d)，意图“整理复现结果写入 §3”；线程可以认领 §2。

**预期动作与回执**：`list_claims` 核实占用，停止对 §3 的编辑；认领 §2、`read_document` 读最新原文，在 §2 末尾写一段标明“待并入 §3”的建议稿，读回核对，再 `send_to_coordinator` 告知建议稿位置和目标。清单保留“○ 待 §3 释放后并入”。对请求人一句：“和 MolCLR 的对比先写在 §2 末尾，§3 正由[MolCLR 复现](#thr_d)整理，放开后再并入。”收到 `claim-released` 后重新认领 §3、重读最新内容、逐项合并并读回；实际并入成功后才能回复“已并入 §3”。

**不应行动**：不换成整篇文档认领来绕过冲突，不释放他人的认领，不因快到期而覆盖 §3，不承诺由协调者代为并入。若两方要把同一结论改成相反版本，停在建议稿并交由成员决定。
